# Administrator navigation and tour calendar

Owner request 2 November 2026: see all panels from the existing administrator login, understand the platform structure, and have an integrated calendar. Existing public pilot exposes only /nautica and marine APIs. Full CRM routes remain closed. Hair and other services must not change.

## Scope and decisions
This is a scoped presentation change in the existing marine screen, not a new permission model or activation of CRM providers. Use the reduced Heili EGM path: self-contained pre-code independent design check and separate post-code review. Five-stage architecture review is not performed because no route/API/schema/guard/integration changes are proposed. Escalate if these boundaries change. New cycle budget 20 reviewer calls/30 reviewer minutes, unrelated to the completed overnight release.

Admin may inspect the crew operations workflow but this is not impersonation and must not claim reduced rights. No synthetic role switch.

Resumen shows counts and upcoming trips ONLY among the API-returned summaries, and working buttons to open panels. Calendario is a read-only monthly calendar plus selected-day list from the same trip summaries, in America/Caracas, Monday-first. Month navigation and Hoy, accessible day buttons, dates not based on browser timezone, cancelled/completed statuses, capacity/reserved info in day list. Opening a trip from calendar/overview selects that trip and opens operations; detail must clear/load as existing selector does. No drag/rebook/write actions. The existing API returns at most 50 prioritized tours, not an exhaustive history. Always display "Vista limitada a los 50 paseos disponibles; no es el historial completo" in overview and calendar. Counters are labeled "En esta vista"; empty days/months say "Sin paseos en esta vista", never claim no tour exists. Calendar month navigation is bounded to earliest/latest returned tour month plus the current Caracas month; current month remains accessible even with zero tours. No exhaustive history or authoritative calendar availability is claimed. Test a truncated 50-row response and limits.

Panels must not reset or remount MarineApp: it is the sole data/mutation/offline owner. Navigation must not discard in-flight or retryable operations. Overview/calendar contain no new backend writes. Existing admin banner becomes role-neutral. Current bottom nav appears only in operations. Admin menu available on empty/error state only once role is obtained; no admin flashes for member or anonymous users.

Clientes y ARM, Agencias and Equipo y accesos are inspectable informational panels with explicit Pendiente/No conectado labels, useful lists of current versus planned capabilities, no fabricated counters/conversations, no fake save/invite/connect buttons, no links to blocked routes. ARM currently only has per-tour draft messages, not active agents or a cross-tour CRM. Agency attribution exists on bookings, external agency portal not yet. Accounts provisioned privately, no online team management yet. Do not imply these previews fulfill the eventual integrated ARM. Maintain Spanish staff UI.
